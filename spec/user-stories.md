# User Stories

Status: full-product human decision active (2026-09-16)

## US-001 — Reproducible contributor build

As a contributor, I want MySD to consume the pinned engine revision so that local and CI behavior
does not depend on whichever MyEngine checkout happens to be current.

Links: FR-001.

## US-002 — Safe public repository

As the repository owner, I want publication to fail on raw reference artifacts so that evidence
collection cannot leak third-party binaries or creative assets.

Links: FR-002, FR-006.

## US-003 — Offline player

As a player, I want service-shaped features to have deterministic local behavior so that the first
release remains playable without ads, payments, accounts, or Arena backend.

Links: FR-003.

## US-004 — Returning player

As a returning player, I want run and profile data to survive lifecycle/process death and supported
schema upgrades without changing replay outcomes.

Links: FR-004, FR-007.

## US-005 — Spec reviewer

As a spec reviewer, I want every state and mechanic requirement to cite accepted evidence or an
explicit product decision so that inferred behavior does not silently enter implementation.

Links: FR-005, FR-008.

## US-100 — Enter the accepted campaign contour

As a player, I want to enter campaign setup and resume/cancel an unfinished local run through the
observed contour without relying on a network service.

Links: FR-100.

## US-101 — Play the accepted early battle contour

As a player, I want to start an early battle, see wave activity, and access the observed battle
controls without requiring unconfirmed mechanics or copied reference content.

Links: FR-101, FR-102.

## US-102 — Choose an enhancement and reach victory

As a player, I want to see the observed enhancement-choice surface and complete the safe local
victory contour with a reward panel.

Links: FR-103, FR-104.

## US-103 — Use roster and local settings surfaces

As a player, I want to open the observed roster and local settings contours while unobserved
upgrade and toggle effects remain explicitly deferred.

Links: FR-105.

## US-104 — Use offline service-shaped boundaries

As a player, I want reward and Arena-shaped surfaces to remain usable through deterministic local
adapters without real ads, payments, accounts, or network matches.

Links: FR-106, FR-107.

## US-105 — Progress through an offline campaign

As a player, I want a complete set of stages with energy, unlocks, stars, replay, and sweep so that
the campaign remains meaningful without an account or connection.

Links: FR-108, FR-112.

## US-106 — Defend through a complete battle

As a player, I want ten-wave battles with several defenses, allies, enemies, bosses, abilities,
speed controls, and both outcomes so that each run has tactical shape and a real conclusion.

Links: FR-109, FR-110.

## US-107 — Shape a run with enhancements

As a player, I want deterministic three-choice enhancement breaks so that a run develops without
making its replay or restore result unstable.

Links: FR-111.

## US-108 — Grow my roster and technology

As a returning player, I want real roster upgrades, loadouts, and prerequisite-aware technologies
so that battle rewards produce lasting local progress.

Links: FR-113.

## US-109 — Use the local shop safely

As a player, I want soft-currency offers to work and ad/purchase-shaped offers to be explicit local
placeholders so that no hidden network or real transaction is required.

Links: FR-114.

## US-110 — Play a local Arena exhibition

As a player, I want a deterministic Arena-like exhibition even though matchmaking and accounts are
intentionally unavailable.

Links: FR-115.

## US-111 — Keep accessible preferences

As a player, I want sound, music, haptics, motion, and readable UI preferences to survive restarts.

Links: FR-116.

## US-112 — Resume the whole product safely

As a returning player, I want active battle and profile progress to restore together without changing
future deterministic outcomes.

Links: FR-117.
