# Balance Plan

Status: original release-one balance authorized; no reference numbers accepted

## Method

1. Record observed timing/range samples as observations, never copied constants.
2. Infer only distributions/relationships with controlled experiments.
3. Establish original baseline numbers that preserve intended pacing, not exact reference values.
4. Run deterministic scenario batches for win rate proxies, leaks, economy curve, build timing,
   enhancement impact, and entity concurrency.
5. Review deltas per content family.

## Gate 2 boundary

The bundle accepts semantic pacing relationships and observed contours only. It does not promote
reference currency, cost, damage, wave, multiplier, or reward values into requirements.

## Implementation gates

- three repeated early battles before any randomness claim;
- critical timings within ±15% only where observation confidence is at least 0.8;
- load benchmark at observed maximum concurrency +25%;
- no unexplained dominant option in the tested starter slice;
- balance changes never alter engine algorithms without a separate ENG card.

## Release-one simulation set

The final batch report covers all six stages, ten waves per stage, every tower/ally/enemy/boss role,
both hero abilities, and all twelve enhancements. It includes no-command defeat, starter-loadout
victory, intentionally weak/strong loadouts, each enhancement in isolation, aggregate resource
conservation, peak entity count, and peak count plus 25%. Balance constants are read from the
versioned original content catalog rather than duplicated in the report.

The first verification run occurs only after the integrated implementation is complete, per the
2026-09-16 delivery decision.
